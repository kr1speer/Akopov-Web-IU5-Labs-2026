## 3. Задание

### 3.1. Основное задание

Необходимо создать простое веб-приложение с выводом карточек и страницей подробной информации по каждой карточке. Проект должен быть организован в виде одностраничного приложения, в котором навигация и отображение контента выполняются средствами JavaScript без полной перезагрузки страницы.

Основные требования:
- инициализация проекта через `npm`;
- подключение библиотек через менеджер пакетов;
- разделение кода на логические модули;
- отображение карточек с информацией;
- открытие подробной страницы по выбранному элементу.

### 3.2. Домашнее задание (Алгоритмика)

В интерфейс приложения необходимо встроить набор алгоритмических задач, адаптированных под предметную область Boeing. В проекте используются задания, связанные с обработкой массивов, объектов, матриц и перестановкой элементов. Каждая задача представлена как отдельная карточка с пояснением и визуальным оформлением.

В приложении реализованы следующие сценарии:
1. сборка позывного рейса из массива данных;
2. очистка диагностических логов от пустых значений;
3. группировка серийных номеров в диапазоны;
4. инверсия очереди с возможностью частичного сохранения элементов.

### 3.3. Дополнительное задание

Дополнительно было реализовано полноэкранное оформление интерфейса в стиле корпоративного сайта Boeing. Основной экран занимает всю высоту окна браузера, а контент размещается на фоне крупного изображения. Для верстки используется Bootstrap 5 и стандартные утилиты позиционирования, сетки и выравнивания.

## 4. Теория и реализация (Примеры из кода)

### 4.1. Архитектура SPA и компонентный подход

**Теория:**  
В одностраничном приложении весь интерфейс отображается внутри одного корневого контейнера. При переходе между разделами страница не перезагружается, а содержимое корня обновляется программно. Такой подход упрощает навигацию и позволяет повторно использовать компоненты.

В проекте запуск приложения выполняется через главный модуль, который получает доступ к корневому элементу и инициализирует главную страницу.

**Пример из кода:**

```javascript
import { MainPage } from "./pages/main/index.js";

const root = document.getElementById('root');
const homeLink = document.getElementById('home-link');

const startApp = (e) => {
    if (e) e.preventDefault();
    new MainPage(root).render();
};

homeLink.onclick = startApp;
startApp();
```

Такое решение показывает, что приложение строится по принципу композиции: главная логика вынесена в отдельный класс страницы, а стартовая инициализация сведена к минимуму.

### 4.2. Структура страницы и работа с Bootstrap

**Теория:**  
Для интерфейса используется готовая сетка Bootstrap 5, что позволяет быстро организовать адаптивную верстку без написания большого объема собственного CSS. Вся страница строится вокруг корневого контейнера, а основная область контента занимает свободное пространство между шапкой и подвалом.

В HTML-документе подключается Bootstrap, задается гибкая вертикальная структура страницы, а основной контент помещается в контейнер `#root`.

**Пример из кода:**

```html
<!DOCTYPE html>
<html lang="ru">
<head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <title>Boeing Fleet</title>

    <link href="node_modules/bootstrap/dist/css/bootstrap.min.css" rel="stylesheet">
</head>

<body class="d-flex flex-column min-vh-100 bg-white">

    <header class="navbar navbar-dark bg-primary py-3 shadow-sm sticky-top">
        <div class="container-fluid px-4 d-flex align-items-center">

            <a href="#" id="home-link" class="navbar-brand p-0 m-0">
                <img src="logo.svg" alt="Boeing" height="25">
            </a>

        </div>
    </header>

    <main id="root" class="container mt-5 flex-grow-1"></main>

    <footer class="py-4 mt-auto border-top text-center text-muted">
        <p class="small m-0">© 2026 The Boeing Company.</p>
    </footer>

</body>
</html>
```
За счет такой структуры интерфейс остается простым, читаемым и легко расширяемым.

### 4.3. Алгоритмические задания и хранение данных

**Теория:**  
Данные для карточек вынесены в отдельный модуль. Это упрощает поддержку проекта, так как контент и логика не смешиваются между собой. Подобная организация особенно удобна для приложений, где список элементов может изменяться или дополняться.

Каждый объект содержит заголовок, описание, тип сложности и текст для подробной страницы. Такой формат хорошо подходит для рендеринга карточек и последующего открытия детального представления.

**Пример из кода:**

```javascript
export const planesData = [
    {
        id: 1,
        title: "Задание 1.1: Сборка позывного",
        src: "./assets/plane1.jpeg",
        text: "Функция concatenate: склейка массива данных о рейсе (номер, пункт, статус) через разделитель для формирования полетной ведомости.",
        type: "Уровень 1"
    },

    {
        id: 2,
        title: "Задание 1.10: Очистка логов",
        src: "./assets/plane2.jpeg",
        text: "Функция erase: удаление пустых записей и ошибок (null, undefined, 0) из диагностической системы бортового компьютера.",
        type: "Уровень 1"
    }
];
```
Такой способ хранения данных делает приложение гибким: новые карточки можно добавлять без изменения основной структуры интерфейса.
